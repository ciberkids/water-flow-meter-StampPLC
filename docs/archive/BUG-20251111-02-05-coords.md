## 1. Bug Summary
- **Observed Behaviour:**  
  1. Live preview coordinates still treat `(0,0)` as near the top-right instead of the bottom-left; labels positioned at `x=0, y=0` do not align with the bezel and maximum values appear inverted.  
  2. Keyboard arrows remain miswired: Up/Down do nothing, Left/Right move elements vertically (left → up, right → down).  
  3. Changing the Theme Editor’s “Transition easing” select still flickers between values; removing the control may be preferable since it adds no value.
- **Expected Behaviour:**  
  1. `(0,0)` should map to the bottom-left corner and `x/y` ranges should represent physical coordinates (max at top-right).  
  2. Up arrow moves elements upward (increase X per requirements), Down arrow moves downward (decrease X), Left/Right should not affect Y.  
  3. Transition easing control should either remain stable or be removed without causing flicker.
- **Repro Steps:**  
  1. Open Design tab, select an element, set `x=0, y=0`, observe it renders away from the bottom-left.  
  2. Press keyboard arrow keys while Design tab active; Up/Down have no effect, Left/Right move vertically.  
  3. In Theme Editor, change Transition easing; dropdown flickers between previous and new values.

## 3. Root Cause Analysis
- **Suspected Module:** Layout utilities, keyboard handler in `App.tsx`, Theme Editor select component.
- **Hypothesis:** Residual portrait/lansdcape math still inverts axes; keyboard mapping helper still uses orientation-based transforms; Theme Editor select still tied to live theme updates causing flicker.
- **Evidence:** Manual testing (coordinates misaligned, keyboard behaviour), existing Playwright tests failing expected behaviour, select flicker observed in UI.

---

## 4. Fix Outline
1. Update layout/clamp helpers so `(0,0)` is bottom-left and max values align to the bezel; ensure tests cover both portrait/landscape.
2. Rewrite keyboard mapping to follow the specified wiring (Up/Down change X, Left/Right inert or follow spec), update Playwright coverage.
3. Remove or stabilize Transition easing dropdown to eliminate flicker (e.g., convert to controlled state or eliminate if unused).

> Keep this scoped strictly to eliminating the defect. No feature expansion.
